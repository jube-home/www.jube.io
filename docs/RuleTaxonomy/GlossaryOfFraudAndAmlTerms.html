    Glossary of Fraud and AML Terms

    G1. Money Laundering Typologies and Concepts

    Bust-out — see G2.

    Cash-intensive business abuse

    Definition: Criminal cash is mixed with legitimate takings of a cash-heavy business (restaurant, car wash, vending, laundromat, nail bar, taxi) so it appears as revenue.

    Data signature: Deposits inconsistent with the business’s size, sector peers, footfall or card/cash mix; very regular, round or just-below-threshold deposits; minimal supplier payments relative to revenue.

    Detection rules: deposits vs declared turnover and peer norms (4); cash-in share and deposit-to-supplier-outflow ratios (4); sub-threshold deposit bands (9); sudden step-up in deposits (4); multiple branches (2); deposits by non-signatories (2/3).

    In Jube: class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #9 Structuring or Threshold Avoidance, using threshold extensions IsJustBelowThreshold and IsRoundAmount, repeated through class 1 or 2; class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count; class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait. Read Behavioral Baseline and Ratio, Structuring or Threshold Avoidance, Cardinality (Same and Different), Link and Network.

    Correspondent banking abuse / nested accounts

    Definition: A respondent bank passes transactions of its own customers (sometimes unknown to the correspondent) through its account.

    Signature: High-volume, high-value flows in many currencies; payments with stripped originator data; payments on behalf of unnamed downstream customers.

    Rules: missing originator/beneficiary information (6); cover payment anomalies (6); high-risk respondent country (6); sudden volume growth vs baseline (4); many distinct ultimate beneficiaries per respondent (2).

    In Jube: class #6 Static and Match Screening, using a List, or a Sanction for regulatory lists; class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count. Read Static and Match Screening, Behavioral Baseline and Ratio, Cardinality (Same and Different).

    Check: the high-risk jurisdiction and respondent country lists must come from an authoritative source your obligations recognise. A human must confirm the source.

    Funnel account

    Definition: An account in one geography collecting cash deposits from many locations and withdrawing the money elsewhere, often across state/country lines.

    Signature: Deposits in many branches/cities followed by withdrawals far away; many depositor locations; rapid debit after credit.

    Rules: distinct deposit locations (2); deposits in one place and withdrawals far away (8); rapid in-out turnover (1/4); sub-threshold deposits (9).

    In Jube: class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count; class #8 Geospatial and Context, using Double geospatial extensions on Payload coordinates; class #1 Velocity and Volume, using a TTL Counter; class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #9 Structuring or Threshold Avoidance, using threshold extensions IsJustBelowThreshold and IsRoundAmount, repeated through class 1 or 2. Read Cardinality (Same and Different), Geospatial and Context, Velocity and Volume, Behavioral Baseline and Ratio, Structuring or Threshold Avoidance.

    Hawala and informal value transfer systems (IVTS)

    Definition: Value moved through trusted brokers with settlement by offset, trade or cash couriers, bypassing the formal system.

    Signature: Business accounts with many small inbound credits from unrelated individuals and outbound payments to trade counterparties or in bulk to a few overseas accounts; narratives referencing “hawala”.

    Rules: fan-in then bulk fan-out (3); narrative terms (7); unlicensed MSB indicators (6); payments to corridor countries (6); high count of third-party credits (1/2).

    In Jube: class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait; class #7 Unstructured Text Screening, using String extensions against a List of terms; class #6 Static and Match Screening, using a List, or a Sanction for regulatory lists; class #1 Velocity and Volume, using a TTL Counter; class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count. Read Link and Network, Unstructured Text Screening, Static and Match Screening, Velocity and Volume, Cardinality (Same and Different).

    Check: money service business licensing and registration requirements, and what counts as an unlicensed provider, depend on jurisdiction. A human must confirm them.

    Integration

    Definition: The final laundering stage, making funds appear legitimate (property, luxury goods, business investment, loans against deposits).

    Rules: property/high-value goods purchases with third-party funds (5); early loan repayment from third parties (4); loans to shell companies (3); investment in assets inconsistent with profile (4).

    In Jube: class #5 Event Sequencing, using in-model Dictionary state or a TTL Counter read across linked models; class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait. Read Event Sequencing, Behavioral Baseline and Ratio, Link and Network.

    Layering

    Definition: Moving funds through multiple transactions, accounts, jurisdictions and instruments to obscure origin.

    Rules: pass-through (4 ratio ~1); chain sequences with multiple hops (5); circular flows (3); multi-jurisdiction routing (8); rapid conversion across currencies/assets (2/5).

    In Jube: class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #1 Velocity and Volume, using a TTL Counter; class #5 Event Sequencing, using in-model Dictionary state or a TTL Counter read across linked models; class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait; class #8 Geospatial and Context, using Double geospatial extensions on Payload coordinates; class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count. Read Behavioral Baseline and Ratio, Velocity and Volume, Event Sequencing, Link and Network, Geospatial and Context, Cardinality (Same and Different).

    Loan-back scheme

    Definition: The launderer lends their own illicit funds to themselves through an offshore entity and repays the “loan” with interest to legitimise proceeds.

    Rules: loan from offshore related party (6/3); repayments by third parties (4); loan proceeds that match prior deposits (5); no commercial rationale (7).

    In Jube: class #6 Static and Match Screening, using a List, or a Sanction for regulatory lists; class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait; class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #5 Event Sequencing, using in-model Dictionary state or a TTL Counter read across linked models; class #7 Unstructured Text Screening, using String extensions against a List of terms. Read Static and Match Screening, Link and Network, Behavioral Baseline and Ratio, Event Sequencing, Unstructured Text Screening.

    Money mule — see G2. (Fraud-related and AML-related mules overlap.)

    Nominee / straw person

    Definition: A person who holds accounts or companies on behalf of the beneficial owner (to hide control).

    Signature: Authorised-signer or power-of-attorney activity by a third party; account activity inconsistent with nominee’s profile; devices/IPs shared with the true controller.

    Rules: shared device/IP between customers (3); activity inconsistent with age/income (4); signatory controlling many accounts (3); document/attribute reuse (3).

    In Jube: class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait; class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation. Read Link and Network, Behavioral Baseline and Ratio.

    Placement

    Definition: Introduction of illicit cash into the financial system.

    Rules: large cash deposits vs baseline (4); structuring bands (9); cash-intensive deposits vs peers (4); purchase of monetary instruments with cash (1/9); casino chip buy-in without play (5).

    In Jube: class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #9 Structuring or Threshold Avoidance, using threshold extensions IsJustBelowThreshold and IsRoundAmount, repeated through class 1 or 2; class #1 Velocity and Volume, using a TTL Counter; class #5 Event Sequencing, using in-model Dictionary state or a TTL Counter read across linked models. Read Behavioral Baseline and Ratio, Structuring or Threshold Avoidance, Velocity and Volume, Event Sequencing.

    Pass-through / “flow-through” account

    Definition: Account used only to receive and rapidly forward funds.

    Signature: Credits and debits mirror within hours; closing balance near zero; very low retained balance.

    Rules: debit-to-credit ratio near 1 (4); rapid in-out sequence (5); low retained balance (4); many distinct senders and recipients (2/3).

    In Jube: class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #5 Event Sequencing, using in-model Dictionary state or a TTL Counter read across linked models; class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count; class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait. Read Behavioral Baseline and Ratio, Event Sequencing, Cardinality (Same and Different), Link and Network.

    Payable-through accounts (PTA)

    Definition: Correspondent accounts where foreign bank customers can transact directly.

    Rules: sub-account volume anomalies (4); direct customer transactions by foreign respondents’ users (3); high-risk jurisdiction share (4).

    In Jube: class #4 Behavioral Baseline and Ratio, using an Abstraction Rule and Abstraction Calculation; class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait. Read Behavioral Baseline and Ratio, Link and Network.

    Round-tripping

    Definition: Funds leave and return to the originator via a series of transactions, often to create false revenue or move funds without apparent source.

    Rules: circular payment flows (3); matched out/in amounts within window (5); same counterparties in both directions (2/3); trade invoices with no goods movement (7/6).

    In Jube: class #3 Link and Network, using an Abstraction Rule with the Search Key inverted to the shared trait; class #5 Event Sequencing, using in-model Dictionary state or a TTL Counter read across linked models; class #2 Cardinality (Same and Different), using an Abstraction Rule with a Same or Distinct Count; class #7 Unstructured Text Screening, using String extensions against a List of terms; class #6 Static and Match Screening, using a List, or a Sanction for regulatory lists. Read Link and Network, Event Sequencing, Cardinality (Same and Different), Unstructured Text Screening, Static and Match Screening.

    Shell company / front company

    Definition: Legal entity with no real operations used to hold assets, receive/pass funds or hide ownership. A front company has some operations that mask illicit activity.

    G8. Rule-Outcome and Response Terms

    Accept / Challenge / Decline / Hold / Review

    Definition: Standard real-time outcomes. Challenge variants: OTP, push, biometric, call-back, device confirmation. Hold: delay payment pending review (common for APP scam risk). Review: route to a queue without blocking.

    In Jube: no numbered class. The docs express outcomes as a numeric Response Elevation on Activation Rules, which the calling channel maps to accept, challenge, decline, hold or review. Read Activation Rules with Response Elevation.

    Alert suppression / de-duplication

    Definition: Avoiding repeat alerts for the same entity and pattern within a cooling window; implemented via hotlists or dictionaries holding last alert time.

    In Jube: no numbered class. Override suppression with an optional Delete Expiry Date, and TTL Counter increments are not suppressed. Read Activation Rules Override.

    Case priority / triage score

    Definition: Ordering of alerts by risk and value; usually a weighted sum of rule severities plus model score (C3).

    In Jube: no numbered class. Case workflow actions carry a priority of High, Medium or Low, and activations are listed by Response Elevation, highest first. Severity-weighted sums are built with pipeline AddScore. Read Creating Case Workflow Action, Working Activations and Rule Authoring Methodology.

    Confirmation of payee (CoP) / name matching at payment

    Definition: Verifying beneficiary name against account; mismatch is a class 6 screening signal and a scam indicator.

    In Jube: class #6 Static and Match Screening, using a List, or a Sanction for regulatory lists. Read Static and Match Screening.

    Customer warning / interstitial

    Definition: Scam-education prompt before payment; “acknowledged warning then paid” is a class 5 input.

    In Jube: class #5 input, with the warning text carried as Response Elevation Content and an optional Response Elevation Redirect. Read Basic Activation Rules and Event Sequencing.

    Hotlist expiry

    Definition: Time-bound listing of a device/session/account after a hit (e.g. 2 hours) to tighten subsequent rules.

    In Jube: class #6 reference data whose values take a Delete Expiry Date, and an Override switch takes one too. Read Lists and Activation Rules Override.

    Payment delay / cooling period for new payees

    Definition: Holding the first payment to a new payee or after credential change for a period; the delay state is a C1 variable.

    In Jube: cross-cutting C1 for the delay-state input. Read Rule Taxonomy.

    Queue / workflow

    Definition: Investigation destinations (fraud ops, AML, mule, sanctions, EDD); each rule maps to one.

    In Jube: no numbered class. Case workflows are the closest construct to a queue. Read Creating Case Workflows.

    Response code mapping

    Definition: Translating rule outcomes into channel-specific codes (auth response, non-monetary event response).

    In Jube: no numbered class. The Response Elevation value is returned in the response payload with its Content and Redirect, and mapping it to channel codes is left to the caller. Read Activation Rules with Response Elevation.

    Rule priority / tie-break

    Definition: When several rules fire, the highest priority determines the outcome (decline beats challenge beats accept).

    In Jube: no numbered class. Priority on Basic Activation Rules orders evaluation for Activation Rule chaining. Response Elevation can only be raised, so the highest value wins when several rules match. Read Basic Activation Rules and Activation Rules with Response Elevation.

    Severity weighting / score aggregation

    Definition: Summing weighted rule hits into an overall score with bands; allows soft signals to combine.

    In Jube: no numbered class. Pipelines accumulate scores with AddScore and CapScore, and decide on them with MatchIfScoreAtLeast. Read Rule Authoring Methodology.

    Shadow mode / silent rule

    Definition: Rule runs and logs but does not act; used for tuning and champion/challenger.

    In Jube: no numbered class. An Activation Rule with Response Elevation switched off still matches, but raises no Response Elevation, and the Basic Activation Rules page gives the example where it drives no Case Creation, Notifications or TTL Counters either. Read Basic Activation Rules.
