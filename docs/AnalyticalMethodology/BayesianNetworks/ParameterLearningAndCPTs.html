    • Parameter Learning and CPTs

    Parameter Learning and Conditional Probability Tables

    Structure learning (hc, tabu, tree.bayes) and hand-drawn structure (model2network) both produce a DAG with no numbers attached — an arc says two variables are dependent, not by how much. Fitting parameters means estimating a conditional probability table (CPT) for every discrete node, or a conditional distribution for every continuous one, from data. bnlearn::bn.fit does this over an existing structure by one of several estimators, selected with its method argument. This file works through the two discrete estimators — maximum likelihood (method = "mle") and Bayesian estimation with a Dirichlet prior (method = "bayes") — then the continuous and hybrid cases, which fit a different kind of parameter (regression coefficients, not a table) regardless of which of those two estimators is asked for.

    BayesianAnalysisWithBnlearn.md, Procedures 4 and 5, already used both bn.fit(..., method = "mle") on a hand-specified structure and bn.fit(..., method = "bayes", iss = 1) on a Tree-Augmented Naive Bayes structure, without dwelling on what separates the two estimators or what happens when a parent configuration is rare or absent from the training data. That is this file’s subject.

    Maximum likelihood: counting and dividing

    Procedure 1: Maximum likelihood estimation on a discrete network

    method = "mle" is the plain estimator: for every node, for every configuration of its parents’ states, count how many training rows fall into each of the node’s own states, and divide by the row total for that parent configuration. No prior belief and no adjustment — the fitted probability for a cell is exactly its observed relative frequency. This is run here on learning.test, a bundled discrete dataset (six variables, all factors, 5000 rows) that ships with bnlearn for exactly this kind of exercise, with structure learned by hill-climbing first so the CPTs are fitted over a real, non-trivial DAG rather than a single hand-drawn arc.

    library(bnlearn)

data(learning.test)
str(learning.test)

dag <- hc(learning.test)
cat("\nLearned structure arcs:\n")
print(arcs(dag))

fitted.mle <- bn.fit(dag, learning.test, method = "mle")
cat("\nMLE-fitted CPT for node F:\n")
print(fitted.mle$F)

    Tool equivalent: none for fitting a CPT over an arbitrary learned or hand-drawn structure. The nearest fitting step under the same maximum-likelihood principle, for the one structure the product does fit automatically, is AdvancedAnalyticsTreeAugmentedNaiveBayesClassifierTrainingService (BayesianAnalysisWithBnlearn.md, Procedure 7’s structure step, with bn.fit(..., method = "mle") matching BayesianAnalysisWithBnlearn.md Procedure 4’s use of the same estimator).

    Procedure 2: The zero-count problem and the Dirichlet-prior fix

    Maximum likelihood has one structural failure mode: a parent configuration that is rare, or entirely absent, in the training data gets its CPT column estimated from very few rows, or none. A column estimated from very few rows can assign a state exactly zero probability purely because that state happened not to occur in a handful of observations — and a zero in a CPT is not a small number, it is a certainty that state can never happen, which then makes every future case in that cell impossible to score rather than merely unlikely.

    method = "bayes" fixes this by blending the observed counts with a Dirichlet prior before dividing: instead of estimating a cell’s probability as n_ijk / n_ij (count in the cell over the count for that parent configuration), it estimates (n_ijk + alpha_ijk) / (n_ij + alpha_ij), where alpha_ijk is a small “pseudo-count” added to every cell before any real data is seen. bnlearn spreads a single tuning constant, iss (imaginary sample size — the total weight of the prior, expressed as if it were iss additional observations), uniformly over every cell of the node’s full CPT: with r states for the node itself and q parent configurations, each cell gets alpha_ijk = iss / (r * q), so alpha_ij = iss / q per parent configuration. This is the BDeu (Bayesian Dirichlet equivalent, uniform) prior described in Scutari and Denis, Bayesian Networks with R, and in the bnlearn documentation for bn.fit.

    The effect is concrete and worth seeing on data engineered to have exactly the failure MLE has: a Parent variable with three levels, two of them common (500 rows each, roughly even splits of a binary Child) and one rare (5 rows, all of which happen to have landed on Child = "x") — the kind of rare-combination cell a real dataset produces without anyone engineering it.

    library(bnlearn)

set.seed(2024)

n.a <- 500
n.b <- 500
n.c <- 5

parent <- factor(c(rep("a", n.a), rep("b", n.b), rep("c", n.c)),
                  levels = c("a", "b", "c"))

child.a <- factor(sample(c("x", "y"), n.a, replace = TRUE, prob = c(0.5, 0.5)),
                   levels = c("x", "y"))
child.b <- factor(sample(c("x", "y"), n.b, replace = TRUE, prob = c(0.4, 0.6)),
                   levels = c("x", "y"))
child.c <- factor(rep("x", n.c), levels = c("x", "y"))

data <- data.frame(Parent = parent, Child = c(as.character(child.a), as.character(child.b), as.character(child.c)))
data$Child <- factor(data$Child, levels = c("x", "y"))

cat("Observed counts, Child by Parent:\n")
print(table(Child = data$Child, Parent = data$Parent))

dag <- model2network("[Parent][Child|Parent]")

fitted.mle <- bn.fit(dag, data, method = "mle")
cat("\nMLE-fitted CPT for Child | Parent:\n")
print(fitted.mle$Child)

fitted.bayes.iss1 <- bn.fit(dag, data, method = "bayes", iss = 1)
cat("\nBayesian (Dirichlet prior, iss = 1) CPT for Child | Parent:\n")
print(fitted.bayes.iss1$Child)

fitted.bayes.iss10 <- bn.fit(dag, data, method = "bayes", iss = 10)
cat("\nBayesian (Dirichlet prior, iss = 10) CPT for Child | Parent:\n")
print(fitted.bayes.iss10$Child)

    Column c is the payoff. MLE assigns Child = "y" a flat zero probability given Parent = "c", because none of the five observed rows in that cell happened to be "y" — any future case with Parent = "c" and Child = "y" is now impossible under this model, not just rare. Both Bayesian fits pull that cell off zero: with r = 2 states of Child and q = 3 parent configurations, alpha_ijk = iss / 6. At iss = 1, alpha_ijk ≈ 0.1667, giving P(y | c) = (0 + 0.1667) / (5 + 0.3333) = 0.03125 — matching the printed 0.0312500 exactly. At iss = 10, the same arithmetic with alpha_ijk = 10/6 ≈ 1.6667 gives (0 + 1.6667) / (5 + 3.3333) = 0.2 — again matching the printed value exactly. Columns a and b, backed by hundreds of observations each, barely move under either prior (0.5160 and 0.3921 against MLE’s 0.516 and 0.392): the prior’s pseudo-count is swamped by real data as soon as there is enough of it, which is the whole design goal — iss matters where data is thin and disappears where it is not. Raising iss from 1 to 10 visibly trades away some of that rare cell’s fidelity to its five real observations in exchange for a less extreme estimate; there is no universally correct iss, only a stated tolerance for how much a handful of observations should be allowed to imply certainty.

    Tool equivalent: none for fitting a discrete CPT under a Dirichlet/BDeu prior over an arbitrary structure. The same problem — a parameter estimate collapsing to a degenerate value because a class/predictor combination is thin or absent — has a shipped answer for the product’s two fitted classifier-shaped families that face it: Jube.Service.Agent.AdvancedAnalyticsTools.NaiveBayesClassifierTrainingRunTools / tool "SubmitNaiveBayesClassifierTraining" and Jube.Service.Agent.AdvancedAnalyticsTools.TreeAugmentedNaiveBayesClassifierTrainingRunTools / tool "SubmitTreeAugmentedNaiveBayesClassifierTraining" both expose a VarianceRegularisation constant on their training DTOs (default 1e-9), described in Jube.Service.Repository.AnalyticsTrainingRun.AdvancedAnalyticsNaiveBayesClassifierTrainingDto as “the constant used in place of a class-conditional variance that would otherwise be zero, undefined or infinite, expressed as a share of that predictor’s overall training variance.” It plays the same structural role as iss here — a floor that keeps a thin or degenerate class/predictor combination from collapsing a fitted distribution to zero or infinite precision — but it floors a Gaussian variance for a continuous predictor, not a Dirichlet pseudo-count over a discrete CPT cell, because neither product classifier fits a discrete multinomial CPT in the first place (both fit a per-class Gaussian per predictor).

    Continuous and hybrid networks

    Procedure 3: Linear-Gaussian parameter fitting on a continuous network

    When every node is continuous, bn.fit has nothing to count — there is no discrete state to tally. Each node is instead fitted as a linear regression of its own value on its parents’ values: bnlearn calls the result a linear-Gaussian node, and its stored parameters are exactly what lm would report — an intercept, a coefficient per parent, and the residual standard deviation. method still defaults to maximum likelihood in this case (there is no meaningful Bayesian/Dirichlet variant for a continuous regression fit, since a Dirichlet prior is a distribution over discrete-cell probabilities, not over regression coefficients — see Procedure 4’s explicit check of this). The bundled gaussian.test dataset (seven continuous variables, 5000 rows, generated to have a real linear-Gaussian structure) is used here with a hill-climbed structure, as in Procedure 1.

    library(bnlearn)

data(gaussian.test)
str(gaussian.test)

dag <- hc(gaussian.test)
cat("\nLearned structure arcs:\n")
print(arcs(dag))

fitted <- bn.fit(dag, gaussian.test)
cat("\nLinear-Gaussian fit for node F (class 'bn.fit.gnode'):\n")
print(fitted$F)
cat("\nclass(fitted$F):\n")
print(class(fitted$F))

    Procedure 4: Conditional-Gaussian parameter fitting on a hybrid network

    A hybrid network mixes discrete and continuous nodes, with one structural restriction bnlearn enforces: a discrete node may not have a continuous parent (a continuous value cannot be “counted” into a discrete CPT cell), so every discrete node must sit at or above the continuous ones it influences. bn.fit’s fitting method for this case is "mle-cg" (conditional Gaussian) rather than plain "mle" — passing "mle" on a hybrid network is rejected outright, since "mle" only knows how to estimate discrete CPTs. Fitting a conditional-Gaussian node whose parents include a discrete variable works by splitting the continuous data into one group per discrete parent configuration and fitting a separate linear (here, intercept-only) Gaussian within each group — so a discrete parent doesn’t contribute a regression coefficient the way a continuous parent would, it selects which of several fitted Gaussians applies.

    Three nodes are constructed here to show both hybrid cases in one small network: A (discrete, root), B (continuous, with discrete parent A — the conditional-Gaussian case), and C (continuous, with continuous parent B — the plain linear-Gaussian case from Procedure 3, chained beneath a conditional-Gaussian node).

    library(bnlearn)

set.seed(99)
n <- 2000

A <- factor(sample(c("lo", "hi"), n, replace = TRUE, prob = c(0.5, 0.5)))
B <- ifelse(A == "lo", rnorm(n, mean = 10, sd = 2), rnorm(n, mean = 20, sd = 2))
C <- 3 + 0.5 * B + rnorm(n, mean = 0, sd = 1)

hybrid <- data.frame(A = A, B = B, C = C)
str(hybrid)

dag <- model2network("[A][B|A][C|B]")

fitted <- bn.fit(dag, hybrid, method = "mle-cg")

cat("\nNode A (root, discrete) parameters:\n")
print(fitted$A)

cat("\nNode B (continuous, discrete parent A) parameters - conditional Gaussian:\n")
print(fitted$B)
cat("class(fitted$B): ")
print(class(fitted$B))

cat("\nNode C (continuous, continuous parent B) parameters - linear Gaussian:\n")
print(fitted$C)
cat("class(fitted$C): ")
print(class(fitted$C))

cat("\nOverall class of fitted network: ")
print(class(fitted))

cat("\nAttempting bayes-method fit on this hybrid network (expect it to be discrete-only):\n")
result <- tryCatch({
  bn.fit(dag, hybrid, method = "bayes", iss = 1)
}, error = function(e) {
  cat("Error: ", conditionMessage(e), "\n")
  NULL
})
