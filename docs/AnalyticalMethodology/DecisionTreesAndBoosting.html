    • Decision Trees and Boosting

    Splits, Probability and Decision Trees

    The original module introduced splitting data into homogenous groups as the foundation of decision trees, using two datasets: an abstracted FedEx equity file (PC_FDX_Close_200x1D_Close_50x1D_10.csv) for regression trees, and a German credit-risk file (CreditRisk.csv) for classification trees. Neither CSV is part of this repository — they were practice data shipped with the original training bundle. Every R block below runs against a locally reconstructed stand-in with the same shape and column intent (a FDX data frame of abstracted numeric predictors and a Dependent percentage change; a CreditRisk data frame of 1,000 loan applications with the same categorical columns the original discussed — Status_Of_Existing_Checking_Account, Credit_History, Purpose, Housing, Savings_Account, and so on — and a Dependent factor of Bad/Good), generated with a fixed seed so every result below is reproducible but will not match the original guide’s screenshotted figures exactly. Category labels were also stripped of characters (<, >=, /) that C5.0’s internal file format cannot parse — noted at the point it first matters, in Procedure 4.

    Procedure 1: Create a Decision Tree using rpart

    A regression tree splits rows into progressively smaller, more homogenous groups by repeatedly choosing the single variable and threshold that most reduces the variance of the outcome within each resulting group. Unlike linear regression, it does not need variable selection up front — it can be pointed at every column and left to find the useful splits itself. Training uses rpart(), naming the dependent variable and . for “every other column as a predictor”:

    library(rpart)

FDX <- read.csv("/work/FDX.csv")

RegressionTree <- rpart(Dependent ~ ., data = FDX)

RegressionTree

summary(RegressionTree)

    The printed tree reads exactly as the original guide describes: an if/then/else cascade down to each * terminal node, for example node 16 — Range_1 >= 1.111349 is false, Min_2 < 0.118419, Skew_7 >= 0.384, PointStep_12_PearsonCorrelation < 0.389 then predict −0.0809. summary() gives each node’s mean, deviance and the competing/surrogate splits considered at that point, which is where the original guide’s per-node error-rate lookup comes from.

    Tool equivalent: Jube.Service.Repository.AnalyticsTrainingRun.AdvancedAnalyticsDecisionTreeRegressorTrainingService, reached through tool "SubmitDecisionTreeRegressorTraining" (Jube.Service.Agent.AdvancedAnalyticsTools.DecisionTreeRegressorTrainingRunTools). It queues a background training run of the same kind of regression tree (a nested sequence of threshold splits fit to minimise variance) and stores the fitted model as an immutable version — nothing is printed to a console, the fit is inspected afterwards through the run’s stored evidence and the model diagram covered in Procedure 2. There is no need to hand-pick or drop predictor columns first, matching the R behaviour described above.

    Procedure 2: Visualise an rpart Decision Tree

    rpart.plot() turns the same tree into a diagram, which for a tree of any size is much easier to read than the nested if/else text — at the cost of usually needing to export the image and zoom in.

    library(rpart)
library(rpart.plot)

FDX <- read.csv("/work/FDX.csv")
RegressionTree <- rpart(Dependent ~ ., data = FDX)

pdf("/work/RegressionTree.pdf")
rpart.plot(RegressionTree)
dev.off()

cat("rpart.plot rendered", nrow(RegressionTree$frame), "nodes to /work/RegressionTree.pdf\n")

    Console output:

    null device 
          1 
rpart.plot rendered 21 nodes to /work/RegressionTree.pdf

    AdvancedAnalytics equivalent: Jube.Charting.Diagrams.Diagram.Tree() → TreeDiagramBuilder (Jube.Charting/Diagrams/TreeDiagramBuilder.cs), which renders a TreeDiagramSpec (a TreeNode tree of split feature/threshold, sample counts, class counts, value, impurity and branch labels) as an SVG using a Reingold-Tilford layout — the same “balanced, centred-over-children” tree shape rpart.plot produces, but laid out deterministically and covered by golden-snapshot tests rather than rendered once into an image you export and zoom into. Diagram.Forest() → ForestOfTreesBuilder does the equivalent for an ensemble (the first N trees of a random forest or boosted model, alongside their variable importances) — see the AdvancedAnalytics equivalent note on Procedure 9. Both live in namespace Jube.Charting.Diagrams, part of the product’s own backend SVG charting library (see Charting).

    Procedure 3: Recalling an rpart Decision Tree

    As with every predictive model in the original guide, predict() takes the fitted object and a data frame of rows and returns predictions in the same row order, which can then be merged back onto the source data frame with dplyr::mutate().

    library(rpart)
library(dplyr)

FDX <- read.csv("/work/FDX.csv")
RegressionTree <- rpart(Dependent ~ ., data = FDX)

RegressionTreePredictions <- predict(RegressionTree, FDX)

head(RegressionTreePredictions)

FDX <- mutate(FDX, RegressionTreePredictions)

head(FDX[, c("Dependent", "RegressionTreePredictions")])

    AdvancedAnalytics equivalent: Jube.Engine.AdvancedAnalytics.Regression.DecisionTreeRegressorRecall. Recall against a trained decision tree regressor is part of the same engine-synced live-model path every other AdvancedAnalytics model uses — there is no separate “recall” step to call by hand; a promoted model’s predictions are produced the same way for a rule, an abstraction calculation, or an agent tool querying it, all reading the one stored model version.

    Procedure 4: Creating a C5 Decision Tree

    Procedure 10: Creating a Gradient Boosting Machine

    A Gradient Boosting Machine is also built from boosted trees, but instead of reweighting misclassified rows it fits each new tree to the residual (roughly, the current error) of the ensemble so far, tempered by a small learning rate (shrinkage) so no one tree dominates. The package is gbm, not GBM as the original guide’s install step named it — R package names are case-sensitive on every platform this guide was validated on, and library(GBM) fails outright.

    library(gbm)

CreditRisk <- read.csv("/work/CreditRisk.csv", stringsAsFactors = TRUE)

set.seed(4210)
GBM <- gbm(Dependent ~ ., data = CreditRisk,
      n.trees = 1000,
      shrinkage = 0.01,
      distribution = "gaussian",
      interaction.depth = 7,
      bag.fraction = 0.9,
      cv.folds = 10,
      n.minobsinnode = 50
)

GBM

pdf("/work/GBMPerformance.pdf")
best_iteration <- gbm.perf(GBM)
dev.off()

cat("Best cross-validation iteration:", best_iteration, "\n")

    Procedure 11: Recalling a Gradient Boosting Machine
