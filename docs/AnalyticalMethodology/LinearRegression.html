    Linear Regression

    Linear regression predicts a numeric outcome from one or more numeric predictors when the residuals are reasonably close to normal. The original course worked against an FDX (FedEx, NYSE) equity file that had already been through Jube’s abstraction engine: a Dependent column (a forward return) plus hundreds of abstracted predictor columns named for the statistic and window they came from (Median_1, Mode_1, Skew_3, Range_2_PearsonCorrelation, PointStep_5_PearsonCorrelation, and z-scored or self-correlated variants of the same). That exact file is not available in this environment, so every snippet below runs against a synthetic stand-in built with the same column-naming shape and the same kind of relationships (a weak overall signal, a couple of genuinely predictive columns, and two deliberately collinear groups so the multicollinearity procedure has something real to find). Coefficients therefore differ from the original screenshots; the mechanics and the shape of the result do not. dplyr and ggplot2 are both in the shared package set, nothing extra was installed.

    Procedure 1: Scanning Scatter Plots for Relationships

    pairs() draws every pairwise scatter plot among a data frame’s columns in one grid, which is the fastest way to eyeball which predictors move with the dependent variable before modelling. Run over a whole abstracted file (hundreds of columns) the grid is unusably large, so the practical habit is to subset to Dependent plus one family of related columns at a time, repeating across families until a feel for the relationships has formed. The original text’s subsetting line had a bracket typo (pairs[c(...)] instead of pairs(FDX[, c(...)])); corrected below.

    FDX <- read.csv("/work/FDX.csv")

pdf("/work/p01_full.pdf")
pairs(FDX)
invisible(dev.off())
cat("Full pairs() matrix rendered over", ncol(FDX), "columns.\n")

pdf("/work/p01_subset.pdf")
pairs(FDX[, c("Dependent", "Median_1", "Median_1_PearsonCorrelation", "Median_1_ZScore",
              "Mode_1", "Mode_1_PearsonCorrelation", "Mode_1_ZScore")])
invisible(dev.off())
cat("Subset pairs() matrix rendered over 7 columns.\n")

    Console output:

    Full pairs() matrix rendered over 11 columns.
Subset pairs() matrix rendered over 7 columns.

    AdvancedAnalytics equivalent: Jube.Charting, Chart.ScatterMatrix() — a scatterplot matrix with histograms on the diagonal, scatters below and correlation cells above, one row linked across every cell on hover. This replaces pairs() as the exploratory grid; never ggplot2 or base R graphics.

    Procedure 2: Creating a Scatter Plot for Closer Inspection with ggplot2

    plot() gives an instant scatter of two columns; qplot() from ggplot2 draws the same relationship with more visual polish for anything that will be shown to someone else.

    FDX <- read.csv("/work/FDX.csv")
library(ggplot2)

pdf("/work/p02_plot.pdf")
plot(FDX$Median_4, FDX$Dependent)
invisible(dev.off())
cat("Base plot() scatter rendered.\n")

pdf("/work/p02_qplot.pdf")
print(qplot(FDX$Median_4, FDX$Dependent))
invisible(dev.off())
cat("ggplot2 qplot() scatter rendered.\n")

    Console output:

    Base plot() scatter rendered.
Warning message:
`qplot()` was deprecated in ggplot2 3.4.0. 
ggplot2 qplot() scatter rendered.

    (qplot() is now a deprecated corner of ggplot2 itself — one more reason it is not a path this product follows.)

    Tool equivalent: Jube.Charting, Chart.Scatter() — scatter and bubble charts with trend lines and R squared, an identity diagonal and log axes built in. Outside the platform this is what you would reach for instead; the product never renders through ggplot2 or a raw R graphics device.

    Procedure 3: Create a Correlation Matrix using Spearman and Pearson

    cor() produces a full correlation matrix over a data frame in one call. method chooses "pearson" (linear) or "spearman" (monotone rank); use = "complete" avoids the whole matrix collapsing to NA the moment any row has a missing value. The matrix can then be subset to just the Dependent column, using drop = FALSE (not the string "false" in the original text) to keep the result a matrix rather than a bare vector.

    FDX <- read.csv("/work/FDX.csv")

Pearson <- cor(FDX, use = "complete", method = "pearson")
cat("Dimensions of Pearson:", paste(dim(Pearson), collapse = " x "), "\n\n")

PearsonDependent <- Pearson[, "Dependent", drop = FALSE]
cat("PearsonDependent (correlation of every column with Dependent):\n")
print(round(PearsonDependent, 4))

    Console output:

    Tool equivalent: Jube.Service.Agent.AdvancedAnalyticsTools.RelationshipsAndRegression.CorrelationTools / tool "CorrelationMatrix" — every pairwise Pearson, Spearman or Kendall correlation in one call, with a matching p-value matrix, pair counts and the strongest pairs pre-ranked with Benjamini-Hochberg adjusted p-values, choosing pairwise or listwise deletion explicitly instead of cor()’s implicit use= behaviour. For a single pair, tool "PearsonCorrelation" (or "SpearmanRankCorrelation" for the rank version) additionally returns a Fisher z confidence interval that cor() alone does not.

    Procedure 4: Ranking Correlation by Absolute Strength

    Both -1 and +1 are equally interesting extremes, so the dependent column is ranked by abs() of its correlation rather than the signed value. The original relied on clicking a column header in the RStudio matrix viewer to sort it, which cannot be captured in a script; order() is the programmatic equivalent.

    FDX <- read.csv("/work/FDX.csv")
Pearson <- cor(FDX, use = "complete", method = "pearson")
PearsonDependent <- Pearson[, "Dependent", drop = FALSE]

PearsonDependentAbs <- abs(PearsonDependent)
cat("Absolute correlation with Dependent:\n")
print(round(PearsonDependentAbs, 4))

cat("\nOrdered highest absolute correlation to lowest (programmatic equivalent of the\n")
cat("manual column-header sort in the RStudio matrix viewer):\n")
ordered <- PearsonDependentAbs[order(-PearsonDependentAbs[, 1]), , drop = FALSE]
print(round(ordered, 4))

    Procedure 5: Adding a Trend Line to a Scatter Plot

    stat_smooth(method = "lm") overlays a line of best fit (with its default shaded confidence ribbon) on a ggplot2 scatter, giving an immediate visual read on direction and strength before any formal model is fitted.

    FDX <- read.csv("/work/FDX.csv")
library(ggplot2)

pdf("/work/p05_trend.pdf")
print(qplot(FDX$Median_4, FDX$Dependent) + stat_smooth(method = "lm"))
invisible(dev.off())
cat("Scatter plot with an lm() trend line rendered via stat_smooth().\n")

    Console output:

    `geom_smooth()` using formula = 'y ~ x'
Warning message:
`qplot()` was deprecated in ggplot2 3.4.0. 
Scatter plot with an lm() trend line rendered via stat_smooth().

    As in the original course, this particular relationship (Dependent against Median_4) is shallow: the fitted slope has predictive direction but very little strength taken alone, which is why the later procedures build a multiple-predictor model instead.

    AdvancedAnalytics equivalent: Jube.Charting, Chart.Regression() — draws the line, and unlike stat_smooth()’s single ribbon it distinguishes a confidence band for the mean response from a wider prediction band for a single new observation (Student t quantiles, polynomial fit up to degree 3), matching what FitSimpleLinearRegression’s predictAt option computes numerically. Never ggplot2 for this in the product.

    Procedure 6: Creating a One Way Linear Regression Model

    lm(y ~ x, data) fits ordinary least squares. Printing the model gives just the intercept and slope; summary() adds standard errors, t statistics, p-values, R squared and the F test; coef() recovers the coefficients at full floating point precision, which matters because the truncated display can round away digits that change a prediction meaningfully (the original text’s misspelled coeefeicents() is corrected to coef() below).

    FDX <- read.csv("/work/FDX.csv")

LinearRegression <- lm(Dependent ~ Median_4, FDX)

cat("print(LinearRegression):\n")
print(LinearRegression)

cat("\nsummary(LinearRegression):\n")
print(summary(LinearRegression))

cat("\ncoef(LinearRegression) at full precision:\n")
print(coef(LinearRegression))

    Console output:

    print(LinearRegression):

Call:
lm(formula = Dependent ~ Median_4, data = FDX)

Coefficients:
(Intercept)     Median_4  
    0.01793     -0.09301

    Procedure 7: Deploying a One Way Linear Regression Manually with Vector Arithmetic

    Deployment is just the fitted formula applied to a column: intercept plus the predictor multiplied by its coefficient, computed once as vector arithmetic over every row at once, then appended to the data frame with mutate().

    FDX <- read.csv("/work/FDX.csv")
library(dplyr)

LinearRegression <- lm(Dependent ~ Median_4, FDX)
intercept <- coef(LinearRegression)[1]
slope <- coef(LinearRegression)[2]
cat("Intercept:", intercept, " Slope:", slope, "\n\n")

ManualLinearRegression <- intercept + (FDX$Median_4 * slope)

cat("ncol(FDX) before mutate:", ncol(FDX), "\n")
FDX <- mutate(FDX, ManualLinearRegression = ManualLinearRegression)
cat("ncol(FDX) after mutate:", ncol(FDX), "\n\n")

cat("head of the new column:\n")
print(head(FDX[, c("Median_4", "Dependent", "ManualLinearRegression")]))

    Procedure 8: Using the predict () Function for a One Way Linear Regression

    predict() (dispatching to predict.lm) takes the fitted model and a data frame and returns the same vector procedure 7 built by hand, without re-typing the coefficients.
